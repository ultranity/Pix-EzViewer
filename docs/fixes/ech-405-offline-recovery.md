# ECH 身份刷新异常与离线恢复

## 已确认的缺陷

- 自动身份刷新在 OkHttp 拦截器中调用 Retrofit 的挂起接口。刷新返回 405 时，`HttpException` 会逃出 OkHttp 的异步 worker；它不是交给 Retrofit 失败回调的 `IOException`。本地回归在修复前直接抛出 `HttpException`。
- 原 API 响应仅在刷新成功后关闭；断网或 HTTP 刷新失败会漏掉关闭。回归在修复前失败。
- ECH 冷缓存离线加载失败会进入 30 秒退避；原实现没有新连接恢复时的负缓存复位入口。
- 列表首次请求失败只调用 adapter 的空视图 API，但没有可显示的错误/重试视图。
- 本地账号异步初始化与首页立即检查账号之间存在竞态。
- User-Agent 中的版本是字面量 `#{App_Version}`，并非实际版本号。已纠正，但没有证据证明它是线上 405 的根因。

## 行为调整

- 自动身份刷新失败转成 `IOException`，保留原因并在所有路径关闭原响应；失败不再作为刷新成功重放原请求。
- 421 与其他刷新失败一样向调用边界报告，不再伪装成成功；协程取消继续传播。
- 调试版身份刷新按钮执行正常刷新，不再把保存的身份改成无效 token。
- 网络恢复监听随列表视图生命周期注册/注销；新连接清除 ECH 失败退避并允许失败空列表重试，保留仍有效的 ECH 配置。
- 列表提供首次加载、加载失败、空结果和重试状态，已有内容在刷新失败时保留。
- 首页异步等待本地账号读取；数据库错误显示重试，不按未登录处理。冷进程恢复且账号未就绪时重新创建首页 tabs，避免恢复片段提前访问账号；这种情况不恢复旧首页片段的临时 UI 状态，热重建仍保留原恢复流程。

## 验证边界

本地测试使用注入的 HTTP 405 / IOException，不发送用户凭据。真实 OkHttp `enqueue` 测试验证刷新 405 进入 `onFailure`，而非作为未捕获异常退出 worker。

当前没有连接的 Android 设备，未完成真机飞行模式、界面和已登录账号的 ECH 验收。外部 OAuth 诊断被自动审批拒绝，尚待用户授权；不能把本地异常处理通过等同于线上身份刷新已恢复成功。

版本号保持 2.3.0 / 230，没有发布或安装到设备。
